# Code Review Guard

在交付代码前执行自检。三模式：

| 模式 | 触发 | 行为 |
|------|------|------|
| **guard-pass** | 完成实现后 | 对 diff 执行自检清单 → 修复违规 → 输出 `code-review-guard: N fixed, M flagged` |
| **review** | 用户说"审查这个 PR" | 走查清单 → 结构化 findings 报告 → 不编辑代码 |
| **live** | 用户要求前置约束 | 边写边遵循规则 → 交付前自检 |

---

## 15 种 AI 生成代码失败模式（蒸馏自 guard-skills）

以下模式是 LLM 在生成代码时**系统性高发**的缺陷。每次交付前扫描 diff 中是否存在：

1. **Catch-all 异常吞咽** —— `catch(Exception)` 或 `catch(...)` 隐藏真实 bug。只捕获已知可恢复类型。
2. **防御不可能情况** —— 类型系统已排除的 null/undefined 检查。信任类型契约。
3. **过早抽象** —— 只有一个实现的 interface/factory/base class。等待第二个 caller。
4. **注释污染** —— 逐行复述代码的注释。注释说 *why* 不说 *what*。
5. **硬编码成功返回** —— `return {"status": "ok"}` 在应做实际工作的函数中。
6. **幻觉 API/包** —— 使用了不存在的 import/外部调用。验证每个 import 在已安装的版本中存在。
7. **无意图命名** —— `data`/`result`/`temp`/`item`。命名应揭示意图。
8. **长函数** —— 超过 20 行的函数。提取子函数或内联。
9. **参数爆炸** —— 4+ 个位置参数。使用对象/结构体参数。
10. **风格不一致** —— 与周围代码风格不同。读后再写，匹配现有模式。
11. **死代码/未用 import** —— 未引用的函数、变量、import、不可达分支。交付前剥离。
12. **Mock 伪装生产代码** —— mock/fixture 数据进入生产路径。Mock 仅限测试中用于系统边界。
13. **Copy-from-similar 语义错误** —— 从类似代码复制但改了意义。从 spec 重新推导而非复制。
14. **YAGNI 违规** —— 零 caller 的配置 flag/env var/抽象层。不写未被请求的功能。
15. **为琐事加依赖** —— 为 <10 行代码能做的事安装新依赖。

## 安全护栏（永不简化）

以下**绝对不可妥协**——即使梯子要求用最简方案：

- 信任边界的输入验证和净化
- 防止数据丢失的错误处理
- 安全措施（auth、加密、权限检查）
- 无障碍基础
- 用户明确要求保留的任何内容

## 自检清单（guard-pass 模式）

交付前逐项走查 diff。每项回答：**有 / 无 / 不适用**。发现违规立即修复。

```
□ 1. 是否有 catch-all 异常吞咽？
□ 2. 是否有对类型系统已保证的值的防御性检查？
□ 3. 是否有只有一个实现的接口/抽象？
□ 4. 是否有注释只复述代码而不说为什么？
□ 5. 是否有返回硬编码"成功"但实际上未做工作的函数？
□ 6. 所有新增 import 是否在已安装版本中存在？
□ 7. 所有命名是否揭示意图？
□ 8. 是否有超过 20 行的函数需要拆分？
□ 9. 是否有 4+ 位置参数的函数？
□ 10. 新增代码是否与周围代码风格一致？
□ 11. 是否有死代码/未用 import/不可达分支？
□ 12. 是否有 mock/fixture 数据泄漏到生产路径？
□ 13. 是否从 spec 推导而非复制类似代码？
□ 14. 是否有未被请求的配置/抽象/功能？
□ 15. 是否为 <10 行代码引入了新依赖？
```

---

## 输出格式

**guard-pass 完成后输出**:
```
code-review-guard: <N> fixed, <M> flagged
- fixed: [具体修复项]
- flagged: [标记为已知取舍的项，附 ponytail: 注释]
```

**review 完成后输出**:
```
## Code Review Guard Findings

### Must Fix (会引入 bug/安全漏洞)
- [file:line] 问题描述 → 建议修复

### Should Fix (代码质量/可维护性)
- [file:line] 问题描述 → 建议改进

### Flagged (已知取舍)
- [file:line] 取舍说明 (ponytail: 标注)
```
